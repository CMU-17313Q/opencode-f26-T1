## Requirement changes

| ID  | Original requirement (P4A)                                                                                      | Revised requirement                                                                                                                              | Why it changed                                                                                                                                                                                                                                                                        |
| --- | --------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R1  | When the fault location is known, show its file and line in the first explanation.                              | Show the complete reported file and line from supported JS/TS stack frames and TypeScript diagnostics.                                           | The implementation can preserve reported locations, but cannot prove which line caused the bug. Explicit formats make the requirement checkable while preserving the request for actionable location evidence.                                                                        |
| R2  | Show the expected and actual values separately when the failing assertion supplies both.                        | Preserve separately labeled values from single-line Bun `Expected:`/`Received:` pairs, including colored output; do not fabricate absent values. | Different test runners and multiline object diffs use different formats. This gives a concrete supported format for the existing Bun workflow while preserving the need to compare expected and observed results.                                                                     |
| R3  | Keep the proposed patch hidden until the student selects Show proposed fix.                                     | Authorize the fix only after unambiguous consent at both guided steps; other replies stop the flow.                                              | This tool accepts educational text and returns a decision; it does not hold a patch or control all model output. Its enforceable responsibility is the consent gate. Explanation/strategy producers remain responsible for supplying patch-free text.                                 |
| R7  | For a filename-only change, update file references while preserving the fault details and test recommendations. | For equivalent structured diagnostic inputs within the existing summary limit, deterministic outputs change only file references.                | Exact model prose is not stable, and different filename lengths can move a truncated excerpt's cutoff. Compare deterministic outputs for complete excerpts within the existing 240-character budget, retaining the original calculator example and preserving its fault/test details. |

R4-R6 are kept because their behavior and examples are concrete, compatible with explicit consent, and feasible to implement. They are not selected for this PR's four properties. A missing implementation alone is not a reason to weaken an interview requirement.

## Running and CI

From `packages/opencode`, run `bun test --timeout 30000 test/tool/guided-debug.property.test.ts`. Each property uses 300 cases with default seed `17313` (override with `FAST_CHECK_SEED`); failing fast-check output supplies the seed, shrink path, and counterexample for replay. Explicit examples retain the original calculator case and the three normal consent paths.

The package is already included as `opencode#test` in `turbo.json`. The PR's Pipeline calls the unit test workflow, which runs this test file through the ordinary Bun test discovery. Each property prints its requirement ID, kind, and successful case count, so the unit log proves it ran even with `--only-failures`. No deployment runs on a pull request.

The discovered location and consent counterexamples are retained as explicit fast-check examples. R7's integer bounds keep both excerpts below the pre-existing summary budget; R2 separately explores larger numeric/scalar values and escaped strings.

Ahmad’s review of PR #40 identified two more R1 counterexamples. The bare frame `at /repo/src/add.ts:12:3` kept the `at` prefix, and `/repo/src/(calc)/add.ts` lost its location in both named frames and TypeScript diagnostics. The parser now handles the frame wrapper separately from the position. R1 keeps all three examples and generates bare frames and paths with parentheses.
