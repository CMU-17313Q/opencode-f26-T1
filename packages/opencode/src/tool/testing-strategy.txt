Use this tool during guided debugging, after `explain_error` and before `guided_debug`, once you know what change you would propose. It builds a testing strategy for the most recent failure in this session; if the student pasted an error instead, pass it as `error`.

Pass `proposedChange` as a short, general description of what the change should achieve, such as "handle empty input". Do not write the fix or any code in it: the student reads the strategy before they choose to see the fix. Do not apply the change. Pass `executed` only for tests you actually ran in this session, with the output as evidence. The result keeps tests that were run separate from tests that are only recommended. Never say tests passed unless the result lists them under "Tests run". Pass the result to `guided_debug` as `testingStrategy`.
